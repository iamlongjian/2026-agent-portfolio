# 前端转 Agent 开发 · 12 周学习与项目计划

> **适用对象**：（TS/React 为主）· Agent 内核零基础 · 当前仅用 Claude Code 辅助编码
**时间节奏**：周内做"无代码的脑内建设"，周末集中实操写代码
**定位目标**：Agent 应用落地工程师 / AI 全栈 / Dify 二次开发 / 智能体平台前端
**核心产出**：3 个可部署演示项目 + 一套面试可用的复盘文档（Portfolio）
**原则**：主线优先做项目，文档与概念为辅；Claude Code 是结对程序员，不是替你生成成品堆项目

***

## 〇、总览与节奏规则

### 每周时间分配（固定，不纠结）

| 时段 | 做什么 | 时长 |
| --- | --- | --- |
| 工作日晚上 | 无代码：读文档、看概念、画流程图、读他人代码、列周末清单 | 每天 40~60 min |
| 周末 | 实操：写代码、联调、部署、写 README、复盘 | 6~8 h |

> **周内铁律**：绝不打开编辑器写项目代码。最多用 Claude Code 问概念、问"这段代码什么意思"，但不动手写。
**周末铁律**：遇到不懂的概念先记下来，周内再查，不要周末卡在一个概念上浪费整块时间。

### 周内每日标准动作（照着做即可）

| 顺序 | 动作 | 时长 |
| --- | --- | --- |
| 1 | 读官方文档 / 看视频，搞懂当天一个核心概念 | 30 min |
| 2 | 画流程图 / 列周末任务清单 / 整理笔记（建议写进本文件的"周复盘"） | 15~30 min |

### 周末高效秘诀

周五晚上把周末任务拆成具体小步骤（写进"周复盘"区）：

- 周六上午：实现 XX 功能（约 XX 行代码）
- 周六下午：调试 XX 逻辑，跑通 XX case
- 周日上午：部署 + 写 README
- 周日下午：查漏补缺、记踩坑

### 前置准备（第 1 周抽空一次性完成）

- [x] Node 20+、Git、VSCode
- [x] 大模型 API 账号（OpenAI / DeepSeek / 通义，选一个，有额度）
- [ ] **部署平台（已明确选型，不再纠结）**：
  - 前端页面（React 对话页、拖拽编排画布）→ **Vercel**（免费 Hobby 套餐，React/Next 一键部署）
  - LangGraph 后端 / RAG 检索接口（SSE 流式服务）→ **Render**（免费 Web Service，常驻服务，SSE 稳定性优于 Vercel）
  - ⚠️ 避坑：Vercel Serverless 函数有执行时长上限，SSE 长流式容易中途断流，Agent 后端不要硬塞 Vercel
- [ ] **向量库（已明确选型，不再纠结）**：
  - Demo2 RAG 知识库 → **Qdrant Cloud 免费版**（原生向量库，LangChain TS 对接资料最多，首选）
  - Demo3 编排面板如需同时存业务数据（工作流模板、对话历史）→ 再考虑 **Supabase（Postgres + pgvector）**
  - ⚠️ 避坑：向量库只存向量与原始文本、提供检索 API，不托管网页/代码，别把它当服务器用
- [ ] 部署拆分方案落地（**从 Demo0 起就执行，中途不改**）：前端 → Vercel；LangGraph/RAG 后端（SSE）→ Render；RAG 向量数据 → Qdrant Cloud
- [ ] 新建 Github 仓库，所有项目放这里，README 写演示链接、技术栈、踩坑记录
- [ ] 仓库目录结构（**周末动手前先想好，照着建**）：

  ```
  2026-agent-portfolio/
  ├── README.md              # 作品集首页（第 12 周完善）
  ├── notes/                 # 学习笔记、周复盘
  ├── demo0-chat/            # 第 1 周：最简流式对话
  │   ├── web/               → Vercel
  │   └── server/            → Render（SSE 后端）
  ├── demo1-react-agent/     # 第 2~4 周：工具调用 + ReAct + 人工确认
  ├── demo2-rag/             # 第 5~8 周：RAG 知识库问答
  └── demo3-flow-builder/    # 第 9~12 周：可视化编排面板
  ```

  > 每个 demo 独立目录、独立 `package.json`，互不干扰，也方便单独部署。

### Claude Code 使用规范（面试护城河，务必遵守）

1. 复杂架构、流程图、方案先自己想清楚，再交给它实现
2. 它生成的每一段 Agent 调度代码，你都要逐行跑通、打断点看懂状态流转
3. 所有幻觉、超时、SSE 断流、工具调用失败的 bug，由你主导排查，它只辅助定位和修复
4. Git 提交按功能节点拆分，不要一大坨一次性提交，注释写清改动目的

**给 Claude Code 的固定 prompt 模板**：

> 我是 7 年前端，正在学习 LangGraph TS 开发 Agent，需要实现【xxx 功能】。
先给我简单方案和流程图，再生成代码；代码里每一处和 Agent 状态流转、工具调用相关的地方，加详细注释。
完成之后，列出 3 个我需要重点理解的关键点，以及我该怎么自测验证。

**遇 bug 提问模板**：

> 我这个 LangGraph 状态机出现【现象】，我已打印 state 日志如下【粘贴日志】，帮我定位可能原因。不要直接给完整替换代码，优先给排查思路。

**周内（无代码）**

- [ ] 看 2~3 个 B 站 LangGraph 入门视频，建立直观印象

**周末（实操 6~8h）**

- [ ] 用 TS 跑通 LangGraph 最简对话示例（不带工具）
- [ ] 搭一个极简 React 对话页，实现 SSE 流式输出
- [ ] 打断点看每一轮 state 怎么变化
- [ ] **部署（注意拆两半）**：前端 `demo0-chat/web/` → **Vercel**；SSE 后端 `demo0-chat/server/` → **Render**
  - 先本地 `localhost` 前后端跑通，再上 Render，最后前端指向后端线上地址
- [ ] 写 README：架构图 + 线上链接 + 踩坑记录

✅ **产出：Demo0 最简流式对话页**

> ⚠️ **别把 SSE 后端塞进 Vercel**：Vercel Serverless 有执行时长上限，长流式会中途断流（详见「前置准备」的部署拆分说明）。Demo0 起就按前端 Vercel / 后端 Render 拆开，避免后面返工。
